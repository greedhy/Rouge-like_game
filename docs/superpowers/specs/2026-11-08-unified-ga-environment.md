# 统一 GA 执行环境设计与审核

日期：2026-11-08。状态：完成源码方案审核，等待 P0 基线合并门槛；此文档不是实现完成证明。

用户已授权顺序：**先审核方案，将现有代码合并到 GitHub 主分支，再开始开发**。本次设计采用兼容迁移，后续按阶段执行，不要求重复确认已经授权的总体方向。

## 1. 目标与范围

将现有原型、组合 GA、专用 GA 和后续新增行为纳入统一目录、契约、验证与运行环境。保留玩家/AI 的 GAS 激活入口、ASC、装备身份和既有伤害通路，将可复用行为从专用 GA 中提取出来。新行为能够声明目标支持、事件输出、取消规则、资源占用和网络职责。

“统一”不表示任意两个 GA 可以相互激活，也不表示所有节点组合都有效。未迁移的完整 GA 可以先登记为受管理入口，但不能因此标记为可组合节点。统一环境必须明确拒绝不支持的连接，而不是静默退化到旧执行器。

全局约束：

- 使用项目当前 UE 5.8、C++、GAS 和 Actor/Mass 通路，不引入第二套 ASC、背包或伤害结算系统。
- 保留已有 GA 路径、技能 Tag、输入槽语义、装备实例身份与存档身份；迁移只改变经过验证的内部执行实现。
- 共享 DataAsset 是只读配置；运行状态放入每次执行实例，不在施法时修改共享 DA/CDO。
- 服务器决定目标、费用、概率、控制和伤害；首实现包不增加客户端预测图。
- 必须遵守 `docs/cpp-readability-standard.md`、`.clang-format`；涉及敌人状态或池复用须遵守 `docs/monster-development-standard.md`。
- P0 主分支合并完成前不编写新框架产品代码或创建新框架资产。
- 首实现包完成不等于整体目标完成；迁移矩阵未清零前不得宣称“全部 GA 已统一”。

## 2. P0：当前工作区基线合并门槛

目标是把现有代码、修复与注释形成可追溯的 GitHub 主分支基线，避免新重构与未提交历史混在一起。
本轮沿用远端已有 code/configuration-only 发布边界：不上传本地 Content 修改、新素材或 LFS 规则；
本地资产集成测试依赖另行保存的素材，不能把代码合并称为完整可复现资产发布。
准确提交和验证范围见 `docs/2026-11-08-ga-baseline-integration.md`。

1. 核对实际远端默认分支、当前分支、上游和远端增量；主分支名称以 GitHub/远端 HEAD 为准，不假定一定叫 `main`。
2. 分类工作区修改：生产 C++、Config、必要 Content、构建/制作脚本、文档；排除 Saved/Intermediate/Binaries、日志、凭据及临时探针。检查新增二进制是否遵守仓库既有 LFS 规则。
3. 审核完整待提交列表，记录代码提交不包含的本地资产依赖；不得用硬重置、清理目录或覆盖用户未保存资产来获得“干净状态”。
4. 对准确候选树运行完整 Editor 构建及相关自动化，保存每项实际结果。若编译/链接因编辑器锁或测试因弹窗阻塞，先解决真实阻塞；不得以旧报告替代本次检查。
5. 有失败测试时先区分候选改动回归、已有失败、环境阻塞，记录具体证据。无法证明可接受的基线不可直接标记为绿色；不得删除断言或只运行易通过的子集来完成合并。
6. 提交候选基线，经正常 push/PR 或仓库允许的正常 merge 合入主分支；不强推，不绕过分支保护。用户已明确授权合并；若 GitHub 需要外部审批，报告具体规则，保持新框架开发门槛未满足。
7. 拉取远端并记录合并后主分支 SHA，确认候选提交被包含；在此基础上创建 `codex/` 开发分支。只有到此才能开始下述实现。

P0 证据应包含：本地候选 SHA、远端主分支 SHA、提交/PR 链接、构建和测试报告、保留的未纳入文件及原因。上传成功或本地提交成功不等于主分支合并完成。

## 3. 当前框架与不能忽略的差异

| 功能族 | 当前入口与执行器 | 配置/连接 | 迁移注意事项 |
|---|---|---|---|
| 前四批 Actor 原型 | `UPrototypeAbility` / `APrototypeRuntime` | Kind；OnHit/OnPeriod/OnExpire | Actor 目标；持续蓝按整秒；部分失败取消整个 Context |
| 前四批混合版本 | `UPureMassAbility` / `APureMassRuntime` | 同类旧 DA | Actor/Mass；持续蓝按 Delta；周期追赶与尾帧语义不完全等同 Actor 版 |
| 第五批 | `UExtensionAbility` / `AExtensionRuntime` / 世界子系统 | Behavior；HitChild/PeriodChild/CompleteChild | 不允许旧连接；Stack/Displace 的寿命跨出发起 GA |
| 第六批范围 | `UBatch6FieldPrototype` / 混合 Runtime | 继承旧 DA 的特定配置 | 跟随开关、波前、减速和地面表现需分解为明确能力 |
| 第六批连锁 | `UBatch6ChainAbility` | 专用 BFS 与预算 | 不是普通 Chain 子节点；提取行为而非嵌套激活 GA |
| 第六批石化 | `UBatch6PetrifyAbility` / Actor 组件 / Mass 状态 | 专用 GA 参数 | 可先提取共享效果服务，再增加组合节点 |
| 时间轴/Stander | `UAbilityTask_RunTimeline` / Stander GA 回调 | 源时间阶段、配置事件或可信 Notify | 服务器单连续无根运动蒙太奇；只有部分 GA 已接入 |
| 其他传统/敌人/武器 GA | 现有专用 GA、任务、Actor | 各自配置和 Notify | 先目录登记，按族补明确适配器；不能因登记即声称可组合 |

审核结论及源码依据：

- `PrototypeRuntime::Tick` 的 Beam 目标失效走 `Finish(true)`，混合版走 `Finish(false)`；后者会触发 OnExpire。第五批 `Finish(true)` 不统一取消共享 Context。新环境需要显式终止原因与取消范围。
- Actor Field、混合 Runtime 和扩展 Runtime 的周期追赶上限/尾帧处理不同。迁移必须保留 `CompatibilityProfile`，以金样测试确认改变；不能单纯改名端口。
- `FPureMassCombatTarget` 只有 Actor 弱引用或实体 ID，`PureMassCombat::Resolve` 没有敌人池 Lease 校验。延迟节点必须额外绑定生命身份。Mass 当前 ID 在单个子系统内单调生成，但不能跨世界用裸 ID。
- 第五批 `Hit` 在伤害前保存位置，`AddStack` 只允许服务端确认命中在致死后继续使用快照。`HitConfirmed` 与 `DamageResolved` 不能混为同一事件。
- 第五批叠层按施法者、EffectId、目标合并，GA 正常结束不会清理该记录；Actor 位移交 RootMotionSource，Mass 位移交处理器。
- 时间轴的任务、GameplayEvent 和 CastId 不自动复制。既有 Notify 实例校验必须保留，不能用“当前播放实例”伪装来源实例；不可将配置事件与 Notify 同时接到同一伤害。

相关源码：`Private/AbilitySystem/Prototypes`、`Private/PureMass/PureMassAbility.cpp` / `PureMassRuntime.cpp` / `PureMassCombatTarget.cpp`、`Private/AbilitySystem/PrototypeExtensions`、`Private/AbilitySystem/Batch6`、`Private/AbilitySystem/Timeline`。动画边界详见 `docs/ability-timeline-framework.md`。

## 4. 统一结构与职责

```text
玩家输入 / AI / 装备触发
  -> 入口适配（GA Commit 或已授权的派生效果请求）
  -> GraphInstance（ExecutionId、源身份、目标令牌、预算、诊断）
  -> 注册节点执行器
       查询/投射物 | 动画时间轴 | 伤害/状态 | 附着/叠层/位移 | 表现
  -> 类型明确的事件端口
  -> 有界事件队列 -> 后续节点
```

- **目录**：登记每个现有原型/GA/资产的实现族、目标支持、生命周期、迁移状态、替代图与验证证据。未知类必须出现在待处理报告中。
- **GraphDefinition**：版本化 DA，稳定 NodeId/TypeId，节点私有配置及连接；不使用枚举顺序作为持久资产协议。
- **GraphInstance**：一次施法的运行状态和资源所有者；记录活动节点、事件队列及取消状态。
- **注册表**：TypeId 到配置类、端口及能力描述的映射；未知 TypeId、错误配置类及重复注册失败关闭。
- **公共服务**：复用混合目标、伤害、状态和表现通路。首包仅新增石化服务，后续逐项抽取。
- **旧实现适配器**：在迁移期保留旧语义；未经公开事件/寿命协议适配的旧 GA 不能作为任意子节点调用。

目标与来源令牌必须在服务器由真实对象捕获，不信任客户端提供的 Lease/RunId。令牌绑定 UWorld、当前 RunId（若存在）、源 Avatar/ASC，目标 Actor 的 Lease 或 Mass 的实际 EntityHandle；每次延迟执行重新解析。致死位置快照是另一种输入，只能用于明确支持快照的节点，不能拿它对失效目标施加控制。

## 5. 事件、结束与资源协议

事件包含 ExecutionId、NodeInvocationId、EventSequence、源身份、目标令牌、位置/方向和结束原因。节点配置 Tag 相同不表示同一次事件：去重按调用实例与序号，允许多段攻击和多个目标分别触发。

端口语义：Started、HitConfirmed、DamageResolved、PeriodElapsed、Completed、Cancelled、Failed；需区分到期/墙阻挡时使用明确原因，不伪装为相同 Completed。普通 Completed 不可在 Cancelled 后补发。

取消范围分 Node/Subtree/Cast；先关闭事件入口，再取消异步任务并释放句柄，最后报告一次终止。不能在回调仍可进入时先销毁所有者。

寿命域：

1. **绑定 GA**：动画/引导/移动占用，GA 结束必须关闭。
2. **独立施法效果**：已发射弹体或延迟区域，按配置允许在 GA 正常结束后存活；源失效仍关闭。
3. **目标持久状态**：石化、叠层等，由原状态组件/子系统管理并具备独立句柄/合并规则。首包石化沿用既有持续语义，不新增“取消本次施法即可撤销所有来源的石化”。

图校验默认拒绝任意连接环。后续重复只能由有界 Period/Repeat 节点表达。新 V1 图默认上限：64 次节点调用、256 个接受事件、32 个同时活动节点、深度 8；每帧最多处理 64 个队列事件，其余下一帧继续，整体预算耗尽则取消整图。旧执行器原 3 层/64 次等限制继续由兼容配置保留，不直接替换。

## 6. 网络与动画边界

首包玩法图仅服务器执行。客户端显示现有 Actor/Mass 石化复制结果；GraphInstance 本身不复制，也不为首包新增客户端图求值。后续持续表现使用可重建状态快照，瞬时表现可以 Cue/消息；不能只靠一次 Multicast 支撑晚加入。

时间轴是动画编排模块，不是图全局时钟。以后通过事件桥接到图；一个蒙太奇只能由一个任务拥有。保持源动画位置为命中时钟、真实播放实例校验和阶段快照；前摇打断/后摇取消、根运动、多段蒙太奇及客户端预测分别作为显式迁移项目，不因统一环境存在就自动放开限制。

## 7. 首实现包：可验证的完整切片

首包交付：目录与迁移矩阵、V1 契约与图验证、目标/源生命令牌、最小有界执行器、Delay 与 Petrify 节点、石化共享服务，以及一个真实 `Delay -> Petrify` GA 样例。

样例使用当前目标任务选择一个 Actor 或 Mass 敌人：服务器复核后 Commit 一次，捕获生命令牌，等待 0.25 秒，再对同一生命施加 1 秒石化。延迟中取消、目标死亡、池复用、源 Avatar 替换或跨世界后，不施加效果。样例仅单目标，与原范围石化是不同技能；不替换原 `GA_PetrifyingGaze`、不自动授予玩家、不占用现有输入槽。样例费用 10 Mana、冷却 2 秒，使用标准 GAS GE；石化材质复用现有资产。

原石化 GA 提取效果调用后保持原半径、费用、冷却、目标过滤、空放消耗和持续语义不变。新服务不负责重复 Commit，也不新增 VFX 或控制规则。

首包不交付：全部资产迁移、可视化图编辑器、装备触发框架、新怪物/AI、客户端预测图、全动画系统重写。它们仍属于总体路线，不能因首包完成而关闭整体任务。

## 8. 完整迁移路线与退出条件

| 阶段 | 交付 | 进入下一阶段条件 |
|---|---|---|
| P0 | 当前基线已合入远端主分支 | 可核对远端 SHA、候选提交、验证报告 |
| P1 | 上述首包 | 真实 Actor/Mass 延迟石化、旧石化回归和资源收尾通过 |
| P2 | 旧 Kind 原型公共行为化、兼容配置 | 18 种 Kind 逐项矩阵有金样与取消/周期/网络证据，现有组合资产逐项对照 |
| P3 | 第五批附着/叠层/位移及分叉连锁 | 跨施法合并、致死快照、位移替换和子系统退出测试通过 |
| P4 | 时间轴/Notify 与 Stander、传统 GA、敌人 GA 适配 | 不重复伤害，前后摇/取消/池复用与动画视觉逐族验收 |
| P5 | 装备派生入口与最终收敛 | 来源实例、换装、递归防护、保存恢复及联机验证通过 |

每阶段实施前基于已实现接口单独细化计划，不能凭本表直接扩大未设计的运行行为。迁移矩阵状态为 `Inventoried / AdapterRequired / Adapting / Verified / Retired`；`LegacyEntry` 是能力声明，不是完成状态。

整体完成须满足：所有现存 GA/原型均有清单行；所有非退役行进入 Verified；不支持组合的原因已消除或得到用户明确范围调整；用户要求保留的能力和资产引用没有丢失；统一制作指南覆盖未来开发；重复执行器只在仍有明确兼容资产依赖时保留。不能靠将遗漏项标成“以后”来清零。

## 9. 验证与交付证据

至少覆盖：准确费用/冷却次数、异步目标生命变化、取消不发完成、错误端口和循环、预算耗尽、清场/旅行/世界退出、Actor/Mass 状态生效和解除、旧技能资产身份保持、多人权威与表现、时间轴源事件去重。测试需有新鲜报告并确认具体用例执行；无界面测试不替代动画/VFX 或双端 PIE。

每一行迁移记录附源配置、目标配置、兼容策略、测试路径、报告、PIE 状态及遗留问题。实现阶段持续更新本文件的阶段状态；本文目前没有任何“已实现统一环境”的结论。
