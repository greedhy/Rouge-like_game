# Stander guard parry design — 2026-11-16

User request: extend the standard player's existing RMB guard with an initial parry window; reflect ranged projectiles, stun melee attackers and trigger the same independent world-slow reward as perfect dodge. This extends the existing equipped guard without adding a skill slot or Startup ability. Prior perfect dodge remains separate and shares the world-time service.

Implementation defaults (agent-selected, tunable): 0.15 pause-aware action seconds from the real guard-open event, 1.0 world second melee stun. Each distinct eligible direct contact during that fixed window is negated; no refresh on success or held input. Outside the window keep original guard damage/counter rules, fees, cooldown and animation events. Preserve current guard direction rules. World-slow reward: 0.2 scale, 0.05 action-second blend-in, 1.2 hold, 0.15 blend-out, source compensation enabled, 3 action-second reward lock.

Reward contract: FGuardParrySettings adds bRewardWorldSlow=true, RewardLock=3 and Reward(FAbilityWorldSlowSettings); bEnabled still gates the full extension. Only the first distinct successful contact in each Guard attempts a reward. Any active world-time request or own reward lock skips it without adding a lock; later contacts cannot retry/refresh. An actual Acquire attempt starts the lock even if rejected. Successful reward is owned by the component independently of the guard and survives normal guard completion, cancellation, counter transition and equipment change until natural expiry. Death/downed invalidation, Avatar/run/life changes, Invalidate and EndPlay release only its own lease. Existing perfect dodge or other world-time leases are never extended or removed. The existing world-time service supports Standalone only; rejected reward acquisition does not undo a successful parry.

Architecture: extend shared Status.GuardWindow/OpenGuardWindow with opt-in settings and a component that binds parry eligibility to the exact guard GE handle and captured Avatar/run/life. Existing Stander fallback guard and real weapon RMB Guard actions opt in. Other guards remain compatible by default. All validation and interception occurs on authority before direct-hit damage and debuff application. DOT/environment/continuous fields are not reflected or treated as melee. Successful direct parry must not merely refund already-applied damage.

Projectile reflection reuses the actual projectile's collision and movement. Transfer authoritative owner, instigator, ASC and execution source to the defender, reverse its current velocity, remove obsolete enemy-source death ownership, reset homing/collision-ignore state, preserve projectile damage configuration and lifetime. Bound reflection count prevents loops. Original attacker must become hostile/valid for collision again; physical reflected contact causes damage through the original damage pipeline. Production EnemySling lifecycle/wall stop must support the new source. Special projectile implementations without this contract remain explicitly outside first coverage.

Melee stun reuses enemy Debuff.Stun/AI/movement control and existing death/pool invalidation; Mass needs its own genuine stun timing/attack-cancellation state, not a stone visual substitute. Delayed callbacks may not affect a pooled enemy's next life. Parry eligibility ends on guard GE removal, cancel, death, Avatar/run change and equipment cancellation. Expiry/cleanup must not remove other control effects.

Assets: inspect the actual Stander fallback and all weapon sets' RMB slots first. Change only configurations whose real action includes Guard, using exact whitelist+backups and independent readback. Preserve current equipment modifiers and all unrelated dirty files. Existing non-Guard RMB skills retain their action.

Validation: early/edge/late guard, held window not refreshing, real Health/debuff suppression, real reflected source/collision/damage, old attacker death after transfer, double callback/loop cap, real enemy stun/expiry/pool reuse and Mass behavior, node cancellation, first-success reward acquisition, active-request/lock rejection without retry, guard completion/cancellation/equipment persistence, source-life cleanup without releasing other leases, actual fallback/weapon configuration including nested reward and unchanged original costs/events, focused then full test_25d. Build and independent disk readback are separate from user PIE/remote visuals.
