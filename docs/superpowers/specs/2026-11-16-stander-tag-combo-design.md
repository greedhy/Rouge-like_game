# 标准近战普攻 1→2→3 与 Tag 接续方案

首批覆盖标准近战人物出生默认普攻与背包装备剑盾后的左键普攻。未来新增连招沿用同一套 Tag 输入、步骤和转移配置，各武器独立选择是否接入。

## 当前行为和时间轴基线

当前编辑器读回确认出生左键由 `GA_Stander_Combo` 接收。`DA_Stander.Combo` 仍有三段，原生代码按 `CurrentCombo` 与 `NextCombo` 选段，`ComboReset` 为 0.9 秒。该 GA 已引用 `/Game/AbilityTimelines/Stander/Sword_Shield/DA_Stander_Combo`，该资产通过 `MontageVariants` 为三段蒙太奇分别配置时序。

装备 `Sword_Shield` 后，`DA_WeaponSet` 把 `InputTag.LMB` 授予 `GA_Attack1`。`GA_Attack2` 和 `GA_Attack3` 已授予但没有输入槽。当前 ASC 的 Held 路径可以在第一段结束后再次激活同一 Spec，装备链路没有选择第二、第三段的逻辑。

| 实际入口 | 第一段命中后时长 | 第二段命中后时长 | 第三段命中后时长 |
| --- | ---: | ---: | ---: |
| 出生自带普攻 | 0.8167 秒 | 0.8000 秒 | 0.8833 秒 |
| 装备剑盾 | 0.15 秒，其中释放 0.05 秒、后摇 0.10 秒 | 0.7333 秒 | 0.0889 秒 |

装备剑盾三份有效引用位于 `/Game/AbilityTimelines/Stander/Sword_Shield/DA_Attack1`、`DA_Attack2`、`DA_Attack3`。读回的是资产配置值，实际视觉时长还取决于帧边界和蒙太奇混出。旧目录中的 `DA_Sword_Shield_Attack1` 属于历史路径。

## 推荐结构

使用一个共享的连招状态机，保存当前步骤 Tag、一个待消费输入、接续期限和本次动作身份。配置属于 DA，状态属于当前 Avatar 和当前普攻来源，服务器在一次输入到达时根据这两者决定启动哪一步。

| 方案 | 取舍 |
| --- | --- |
| 由共享输入入口接续已经授予的动作，推荐 | 出生沿用同一 Spec 选不同段，装备剑盾选现有 `GA_Attack1/2/3` Spec。每个动作保留原费用、蒙太奇、时间轴和独立技能身份。需要在 ASC 明确消费输入，并在当前 GA 正常释放占用后调度下一次激活。 |
| 在单个长生命周期 GA 内播放三段 | 动画编排集中。装备剑盾需要重组分段 Commit、取消、装备精确技能匹配与原独立 Spec，适合未来需要跨段持续占用的专用技能。 |

`InputTag.LMB` 每次只由当前普攻来源接收。连招路由识别当前生效的输入绑定。装备路径只允许选择当前武器组实际授予的精确 Spec。出生路径把选中的步骤 Tag 交给同一个 `GA_Stander_Combo`，由它解析对应 `FSwordStrike`。服务器在派发时绑定一次性动作上下文及目标 Spec，GA 激活时消费。衔接调度在上一段 EndAbility 收尾后执行，按正常 GAS 条件独立激活。客户端只提交控制输入 Tag，武器归属、当前段和允许的后续段均由服务器确定。

### Tag 接口

| 字段 | 示例 | 职责 |
| --- | --- | --- |
| `ChainTag` | `Combo.Stander.SwordShield.Light` | 标识当前连招配置，出生与装备可选各自的配置。 |
| `StageTag` | `Combo.Stage.Light1`、`Combo.Stage.Light2`、`Combo.Stage.Light3` | 定位当前配置内的步骤和动作定义。 |
| `InputTag` | `InputTag.LMB` | 接续入口使用 `FGameplayTag` 参数。后续可给同一段配置轻击、重击等不同输入。 |
| `ActionTag` | `Abilities.StanderWeapons.Sword_Shield.Attack2` | 精确解析已授予技能，继续供现有装备词条、费用、冷却和动作识别使用。 |

每条转移以 `(FromStageTag, InputTag)` 精确匹配得到 `ToStageTag`。初版配置 `Light1 + LMB → Light2`、`Light2 + LMB → Light3`，`Light3` 正常结束后回到入口。左键后续调用形态为 `RequestComboInput(FGameplayTag InputTag)`。未来需要由统一 GA 图调用时，通过类型化 Tag 输入和注册策略调用同一服务。校验时拒绝重复转移、缺失步骤、无入口、无可用动画时间轴、跨武器动作引用、非预期循环以及会与既有输入抢占的配置。

### 联机预测与回滚

当前首版是服务器权威接续。`InputTag` 用于选择转移，传入上一段的 `StageTag` 只能描述请求的前置动作。两个 Stander GA 前端均为 `ServerOnly`，现有 `UAbilityTask_RunTimeline` 也只在权威端运行。

UE 5.8 本机源码 `GameplayPrediction.h` 的 Dependencies 章节将两件事分开。客户端由有效预测作用域生成 `FPredictionKey`，可以登记预测键间的拒绝依赖。服务器则需要独立检查前置条件。文中 `GA_Combo2` 要求 `GA_Combo1` 授予的 Tag，是给后续 GA 增加权威激活条件。`GameplayPrediction.cpp` 的 `AddDependency` 传播键的拒绝，`AbilitySystemComponent_Abilities.cpp` 的 `ClientActivateAbilityFailed` 按 Spec 和当前预测键结束被拒绝的激活。完整连招状态和项目自定义表现仍由接入逻辑负责清理与对账。

若后续要求客机立即出招，保留同一个 `RequestComboInput(FGameplayTag InputTag)`，增加以下接入：

1. 每次合法接续用一次性记录绑定当前 Avatar、装备授予代次、前一段动作实例、允许的目标段和接续期限。前一段正常结束后记录才可消费。可以用 `State.Combo.Ready.Light2` 一类持有 Tag 做 GAS 激活门禁，并校验记录本身，避免迟到或旧连招产生的同名 Tag 被误用。由于当前设计在上一段结束后开下一段，接续 Tag 由连招状态持有并限时回收，上一段 GA 的 `ActivationOwnedTags` 会随结束移除。
2. 为选中的普攻入口接入 `LocalPredicted` 或单独的客户端表现前端。观察下一次按键时参考引擎 `UAbilityTask_WaitInputPress` 建立新的 `FScopedPredictionWindow`，使用有效预测键的配对网络路径。若按键只入缓存，异步时间轴结束时的预测需要独立的有效作用域或项目级确认协议。初始激活键只对原作用域有效。
3. 把每次预播蒙太奇、缓存和本地占用绑定到该段的尝试身份。服务器拒绝第二段时清除第二段及其未确认后续第三段的本地表现，并按最后确认状态恢复。服务器继续负责伤害和控制。联机验收须覆盖前段被拒绝、后段先预播、前段成功但后段失败，以及旧确认或拒绝抵达时新连招已经开始。

## 操作和衔接时点

1. 左键按下、角色空闲且没有可接续的连招时启动第一段。首版建议只消费 `Pressed`，一次按下最多提出一个接续。按住自动连打可作为同一状态机的输入策略按武器启用。
2. 从本段配置的最早接续源位置起，处于最后 0.15 动作秒内的输入可缓存一条。最早位置应在接触生效点或之后，兼顾短后摇与按键容错。缓存只绑定本段，重复按压无法预填第二个后续步骤。进入窗口以当前蒙太奇播放位置和时间轴映射为准。
3. 本段正常结束后消费缓存并请求下一段，动画按已配置的结束点衔接。释放与后摇完整推进。没预输入时，可在结束后 0.9 动作秒内重新按下接续。超时、第三段完成或被打断后，下一次输入从第一段开始。
4. 挥空可继续连招。有效完成以播放实例正常结束并经过本段应执行的接触事件为准。伤害是否命中目标不参与连段推进。打断、动作启动失败、死亡、倒地、眩晕、换装或卸装、Avatar/Run 更换均清空对应状态和缓存。复核 Spec、装备实例/授予代次及动作实例后再消费，拒绝晚到的回调。缓存交给服务器按一次性序号消费，输入阻挡期间清除或拒绝缓存。

## 资产和实现顺序

1. 先冻结现有各段时间轴读回的蒙太奇绑定、阶段名、源区间、实际时长、混出及事件。装备第一、第三段直接复用当前时间轴。先以原第二段时长打通 1→2→3，再单独调第二段。若试玩节奏要求第二段也短，可先试命中后 0.05 秒释放加 0.10 秒后摇，具体源切点按动画姿势和混出复核。出生三段首轮复用各自的现有变体，统一手感时再单独调这组三段。
2. 接入共享连招配置和共享输入行为。让 `UMyAbilitySystemComponent` 的 Tag 输入只把匹配且启用的普攻交给状态机。现有武器动作前端继续走 `UAbilityTask_RunTimeline`。出生普攻在接入时使用同一个时间轴任务处理本段开始、源位置和真实结束；保留该 GA 其余模式的现有前端。完成事件必须能区分自然结束和接触之后的外部中断。
3. 每段在真实源接触时调用现有 `Combat.CharacterStrike` 动作一次，沿用该段原有伤害、范围、命中特效、阵营、房间过滤与暗金装备身份。当前普攻每段 0 消耗、0 冷却。复用现有 Commit 路径和每次动作会话，用动作身份和事件序号拒绝重复命中。空挥、帧跨过事件以及中途被打断分别验证。
4. 按 `build-ga` 完整编译并对目标资产做白名单修改、独立读回和回归。PIE 使用真实左键分别验证出生、装备剑盾和卸装后的 `1→2→3→1`，缓存、超时、按住、快速点击和 Actor/Mass 单次扣血。对比第一、第三段改动前后的恢复时长与源命中帧，复核第二段新节奏和三段混出。格挡、翻滚、慢动作、受控、换装同武器族和断线/旅行分别检查状态收尾。联机以服务器收到的合法按下输入作权威决策，另测主客机时延和蒙太奇复制。

本文件为设计审阅稿。0.15 秒缓存与按下接续是建议值，0.9 秒接续期限沿用出生连招配置。在 `Saved/GAAuthoring/StanderCombo/design-review/live-readback.json` 可核对本次只读资产证据。
