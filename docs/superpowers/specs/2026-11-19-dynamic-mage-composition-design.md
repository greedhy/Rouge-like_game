# 法师技能运行时组合：需求边界与验收设计

日期：2026-11-19。状态：用户已确认并授权实施，开发中；本文件不是测试通过报告。

## 1. 用户目标与已确认边界

玩家在游戏运行中修改一个技能的组成行为，而不是命中后激活另一个完整 GA。核心例子：火焰箭真实命中 → 等待 → 搜索周围一个未命中敌人 → 从命中处生成下一支火焰箭 → 等待真实命中再继续。复用的是闪电链的传播算法，投递、伤害和表现仍由所选火焰箭片段决定。

本轮用户已明确选择 **开发测试面板＋真实施法验证**。正式符文掉落、三选一、经济平衡和局内存档持久化不属于本轮。运行时产生新行为配方/内存图，不编译或生成新的 UClass/蓝图 GA；不要求为每种组合预制独立 GA 资产。

全部工作在本地 main；保留既有未提交 Source/Config/Content 修改，不自动提交或推送。当前工作区已有大量并行/既有修改；写入前逐文件基线及所有权检查，构建和 UE 资产写入串行协调。

## 2. “所有法师 GA”的精确定义

以 [逐资产清单](../../ga-dynamic-mage-inventory.json) 和 [行为审计](../../ga-dynamic-mage-audit.md) 为范围基线，不按 GA 名字猜测。

| 范围 | 本轮职责 |
|---|---|
| 三个当前技能目录的 Mage 身份：60 个身份、86 个类版本 | 全部审计与兼容验证；Actor/Mixed 同身份版本分别登记 |
| 其中实际玩法：56 个身份 | 复用或拆分其必要逻辑，通过运行时图还原；动态替换能力按真实行为轴开放 |
| 三个旧占位被动 | 保护原激活/停用/表现；当前没有吸血/回蓝/护盾结算，不按名字补造玩法 |
| ListenForEvent / Listen_New | 作为基础设施保护，不作为面板中的自由战斗片段 |
| PerfectDodge / WorldSlow / DelayedPetrify | 保护相关基础/样例入口；已有防御/时间策略不重复实现，保留当前限制 |
| Stander、剑盾及其他武器 GA、敌人 GA/AI | 不重构；共享服务被修改时运行相关回归，不将它们扩展为本轮内容 |
| 新发现的法师候选 | 先补清单并解释是否实际可达；不能悄悄遗漏，也不自动把测试/敌人类当作法师技能 |

本轮不承诺任意节点的全部排列都合法。承诺 100% 清单覆盖、实际已有功能的必要拆分、所声明的组合合同可用，以及非法组合在执行前明确拒绝。不能为了缩小工作量将尚未拆开的宏节点标为“已可自由组合”。

## 3. 架构选择与替代方案

采用 **保留 GA 前端＋共享行为模块＋运行时配方编译为 Schema 2 图**。

- 原前端继续拥有输入、目标确认、动画/Notify/Timeline、原费用和冷却。
- 查询、调度、投递、传播、效果、状态和表现按照真实可替换职责提取为共享实现。
- 原 GA 与新节点调用相同共享实现；旧 Driver 可保留兼容调度壳，但不能长期保留另一份相同算法。
- 所有执行仍经原 GraphInstance/注册策略及 Actor GAS/Mass/状态服务，不增设第二套技能执行器，不嵌套激活完整旧 GA。

其他路径不符合当前要求：只包一层 Legacy 节点不能复用其内部传播算法；一次性重写所有旧 GA 会扩大动画、费用、存档及调参风险；为每种组合制作蓝图无法满足游戏过程中动态生成。因此沿用现有框架的共享拆分是本轮推荐路线。

## 4. 运行时数据与所有权（以下为拟新增合同）

### 4.1 基础技能与片段目录

稳定基础技能 ID 指向原身份/前端和默认行为配方；片段目录登记可选的行为策略、配置类、输入/输出、目标类型、寿命、表现资源及预算成本。动态组合使用原型行为，不引用另一个完整 GA 的激活流程。

片段和配置可以是持久资产；组合后的最终图只在运行时内存中生成。保留原资产数值作为来源，禁止为动态玩法修改共享 DA/CDO。所有资源在打包时可通过稳定引用/资产目录收集，不依赖编辑器 Python 才能运行。

### 4.2 玩家配方组件

组件隶属现有 PlayerState/ASC 所有者，服务器持有；不创建全局单例或另一套 ASC。

记录 BaseAbilityId、修正来源唯一 ID、参数、确定性顺序、RecipeRevision、编译摘要及错误。相同来源更新替换其旧贡献，删除仅移除本来源。新配方先构建/校验，成功后原子替换；失败保留上一有效版本。

默认没有动态修正时完全走原兼容路径。配方修正不自动让未学习技能变为已学习；测试授予是可恢复的开发操作。多玩家同一基础技能的配方隔离。

PlayerState 销毁时组件清理缓存和委托；Avatar 更换后原施法因生命令牌失效，配方配置是否保留与角色职业匹配规则一致。测试退出显式移除本次来源和临时授予，不清空全部 ASC。

### 4.3 配方编译器

输入为稳定基础配方、合法片段和参数，输出为内存 Schema 2 图及诊断，不负责伤害或生成 Actor。

负责：数值组合、替换/追加顺序、端口匹配、Actor/Mass 支持、持续/独立寿命、预算展开、静态循环检查、资源引用与本次身份。禁止依赖 GE 遍历顺序选冲突胜者。不同元素/投递替换无明确优先级时拒绝并显示冲突。

参数修正复用当前暗金共享入口，必须明确每种修正的唯一消费点。原动作已应用的装备倍率不能由编译器重复应用。零修正兼容模式保留旧读取时点；新增动态模式在本次激活被接受后、等待目标或动画事件前冻结配方版本，费用和装备值按其明确合同冻结。

修改配方影响下一次施法；在途弹体、持续区域和已移交世界的独立图持有旧版本。输入目标模式、施法验证、Commit 和执行始终使用同一本次定义，不能仅在 Execute 内临时改共享 Graph 字段。

### 4.4 投递回执与传播状态

每次投递有 RootCastId、PropagationId、StepId 和唯一回执身份；结果至少包括 Hit、Blocked、Expired、TargetLost、Cancelled，并携带真实确认命中位置、方向和原目标生命身份。

投递和效果分离，保持唯一伤害所有者。原弹体由内部伤害改为外部 payload 时，必须显式关闭原伤害通路；不能原弹体先扣血、图再扣一次。旧原生入口通过兼容适配调用相同命中实现。

传播状态持有剩余步数、已访问原生命、衰减和根预算。散射/分支可有各自历史，但共享根生成预算，不能每生一支箭重置全部跳数。每步回执只接受一次；取消、反射/归属变化、来源失效和重复通知不得恢复旧步骤。

有界重复由注册传播/调度策略管理，图保持 DAG。可等待的子投递是同一图执行内的受管调用，不启动第二个完整 GA、不创建第二套调度器；节点、子调用、事件和物理生成都计入根预算。

普通有限施法沿用当前默认上限（64 次调用、256 个累计事件、32 个活动节点、深度 8、每帧最多 64 个事件），超额按明确失败路径收尾。对原有无限引导/被动，不能因改用动态图而在第 256 个事件被截断：保留明确登记的持续执行合同，限制活动资源、队列、每帧工作量和单位时间派生量，正常持续时间仍由松键、资源和原寿命决定。持续策略必须显式登记并测试；不能只填一个兼容字符串绕过预算。多次派生在同一根上下文计量，禁止另起独立根重置限制。

长期传播不依赖首目标继续活着；首击后保留历史命中位置，下一目标重新查询和捕获。活目标控制仍必须 Resolve 原生命，不能复用数字 ID 或对象地址。

### 4.5 时序、状态与表现

拆分范围包括审计表中的所有行为轴：目标查询、直线/追踪/穿透/往返/环绕投递、散射、逐跳/BFS、周期/布防/延迟、锚点/附着转移、波前、叠层阈值、受控位移、伤害/状态/OwnedGE。

旧 profile 保留长帧追赶、尾帧、耗蓝及正常结束规则；新调度合同不得抹掉原差异。跨施法叠层继续由现有世界状态持有者管理，不能塞进每次图的临时局部变量；抽取共享接口，保留状态键和所有权转移。

表现资源使用稳定资源引用，复制必要的本次范围、方向、缩放、速度、端点和寿命。服务器临时 DA/图不作为可自动解析的复制资源。逻辑范围和表现参数共用同一份冻结数据；服务器唯一决定伤害，客户端只表现。

正常 GA 结束与取消、弹体命中与超时、宿主死亡与池回收分开处理；取消先封回执入口再停止策略、解绑、归还移动租约并清所属对象/GE。保留现有 Run/Avatar/ASC/池租约/MassHandle 校验。

动态模式的持续效果保留来源/目标生命周期约束，但已到达命中的位置可用于后继位置效果。是否在施法前端正常结束后继续，使用原有 BoundToAbility/IndependentCastEffect 归属；显式取消不能被伪装成正常结束来保留本应撤销的后继。

## 5. 开发测试面板与实际施法入口

面板为 Development/Editor 开发功能，显式命令打开；不替换正式技能菜单、不修改玩家存档。可在玩家有经验/关卡进度的情况下使用，但自动生成靶场/临时授予仅限明确的测试上下文，不能污染正常房间遭遇。

至少提供：

1. 基础法师技能选择；显示当前入口、默认/动态模式、Actor/Mass 支持。基础设施和占位项显示保护说明，不提供虚构战斗效果。
2. 按行为轴选择投递、传播、调度和效果片段，以及有限数值参数。允许的跨轴组合依据类型/能力合同校验，不为每一对组合写特判。
3. 应用/移除动态修正、恢复原配方；显示 Revision、图摘要、预算及可读错误。非法参数不替换有效配方。
4. 临时使用真实法师主动或被动槽，接入原 ASC 与实际施法输入/目标任务/动画事件。不得用直接调用伤害服务代替真实施法。
5. 可查看事件记录：原施法、每次投递/命中、目标身份、等待、下一步、费用和终止原因。测试工具中可以显示技术字段。
6. 退出精确恢复临时改动的授予、槽位、修正、面板焦点与所属资源。保留测试前的其他技能、装备和属性。

服务器拥有配方修改权；开发 RPC 只提交已登记 ID 和有界参数，不接受客户端任意图/UClass。客户端显示配方摘要和编译反馈，真实技能使用既有输入/TargetData 通路。至少验证 Listen Server 房主/远端配方互不污染。

## 6. 分层测试与验收目标

### A. 审计与配置

- 清单 90 行都有范围结论；60 身份/86 目录版本无缺漏，同身份不同实现分别登记。
- 每个实际玩法映射到共享拆分行为和可生成的默认配方；占位/基础设施不以缺少功能为由伪造实现。
- 保存前后核对资产字段/包指纹，所有白名单外调参不变。优先不修改原 GA/DA 包；确需接入字段时独立读回。
- 每个新策略具备正例、非法参数/端口/目标反例、取消/来源失效清理例。非法配方保留上一有效版本。

### B. 原 GA 兼容与动态复原

- 每个受影响行为先运行旧功能基线，再抽取。原生入口和图入口执行实际共享逻辑，不能保留两份同名算法通过测试。
- 86 个目录版本均有逐资产兼容结果；56 个实际玩法身份逐版本生成默认内存配方并执行功能复原。对照其原目标支持；原 Actor-only 不虚称支持 Mass。
- 检查实际目标/血量/状态、命中数量、时序、原费用与冷却、持续/结束、资源数、GE 句柄与清理。随机分支固定随机条件或用确定性边界，不用宽容差掩盖差异。
- 确定性事件时序容差为声明测试步长内，命中/费用/结束次数必须精确；物理/渲染误差按各测试记录，不能把计时器/Notify 两条伤害都保留。
- Actor/Mass 声明双支持的所有拆分行为分别实测，至少一例两种目标交错；动态图新目标支持单列，不改变旧资产能力声明。

### C. 新动态组合（最低必测集）

| 场景 | 必须观察的结果 |
|---|---|
| 火焰箭逐跳 | A 真实命中后等待，下一支从命中位置飞向 B；B 未真实命中前没有 C；火焰 payload/表现/冲量一次，无隐藏雷电伤害 |
| 传播边界 | A 致死仍继续；无下一目标、撞墙、超射程、目标失效和飞行超时正确结束；下一生命不被旧回执认领 |
| 散射＋投递修改 | 多支箭能替换追踪/穿透及命中效果，独立回执与共享总预算都有效 |
| Emitter＋替换投递 | 换成火箭/直线束后仍按真实成功次数、索敌和周期工作 |
| Field/Trap/Delay＋效果替换 | 范围/布防/延迟与 payload 独立，取消不产生正常到期爆炸 |
| Attach＋周期效果 | 跟随、转移、宿主失效与每次效果独立且不跨生命 |
| Stack＋阈值效果 | 多次施法共享正确叠层，效果可换，正常/致死触发与回收去重 |
| 位移完成后范围效果 | 位移被阻挡/取消时按合同输出，移动租约和后继不会遗留 |
| Wave＋状态 / 点阵＋效果 | 空间推进/顺序与状态效果可更换；不重复命中或作用于池新生命 |
| Orbit / Channel＋效果 | 独立维持/补充/攻击信号与 payload；松键/停用/死亡后资源全部归还 |
| 配方版本 | 同一 GA 在本次游戏中切换至少两种未预制图；在途保留旧版本，后续施法用新版本，撤销恢复原技能 |

新组合必须由运行时解析产生，执行记录包含配方版本、图摘要和实际行为。不能在测试前先烘焙一个组合 GA 再以其通过作为动态生成证据。

不穷举无限参数组合；交付所有基线复原、每个共享策略、允许的端口/跨轴连接以及上述代表场景与失败边界的覆盖表。

### D. 游戏内与联机

- 开发面板在真实法师、实际输入、鼠标目标和原动画/Notify 下完成上述组合施放；以本轮新鲜 PIE/运行回执记录，不沿用旧菜单验证。
- 逐技能动态默认配方有游戏内施法检查记录；渲染检查与自动化属性检查分开。真实动画/范围/粒子朝向和可读性最终由用户 PIE 验收。
- Listen Server 两玩家至少覆盖逐跳弹体、持续场和一个被动/状态组合：远端改配方/输入、服务器一次结算、双方表现及配方隔离。保留当前明确 Standalone 的世界时间效果限制。
- NullRHI 自动化不算视觉或完整双端施法通过；未完成项保持 Pending，不用构建成功替代。

### E. 回归与证据

- 完整 Editor Development 构建通过；运行匹配专项和全量 `test_25d`，非零测试、失败/未运行均为零。报告绑定当次 Source/Config/DLL/资产指纹。
- 若既有未提交修改导致失败，保存实际失败证据和原基线，不改无关模块来伪造全绿。
- 更新逐 GA 台账的实现/自动化/游戏内/视觉/网络状态、当前调参入口、组合制作流程和新增策略范例。

## 7. 执行阶段与停止条件

1. 本设计确认后制定实施计划；冻结当前只读资产/原行为基线和完整逐技能测试目标。
2. 先完成统一配方入口、回执协议和单链火箭纵向切片，验证实际游戏输入及 Actor/Mass；这是后续拆分的结构验证，不是全量任务完成。
3. 按投递/几何与时序/环绕引导/附着叠层位移/状态被动等行为族依次提取，保留原宿主兼容壳并逐项复原所有清单项。
4. 完成所有新组合、面板、独立资产读回、全量回归与双端验证，再交用户 PIE 验收。

遇到 DLL 占用先完成独立工作并请求用户保存、结束调试和正常关闭；不强制退出或覆盖未保存资产。存在未定义行为、与其他任务冲突或无法保持原兼容的改动时，给出具体冲突与最小选择再暂停相关部分。

## 8. 实施状态与证据入口
