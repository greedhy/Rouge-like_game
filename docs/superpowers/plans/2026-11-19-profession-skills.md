# 职业技能学习

技能目录行增加 RequiredProfession，旧技能默认法师，当前三项 ArtBatch 近身技能设为 Stander 并追加到标准角色目录。普通近战技能通过人物技能页学习和装备，装备授予的武器技能继续由装备管理。

界面从当前角色目录构建职业技能列表，服务器在授予学习资格、消费技能点和装备时验证职业。无技能点、无有效状态或伪造目录外技能的请求直接拒绝。旧存档恢复时跳过不属于当前职业目录的技能，后续重新获得本职业可学习资格。

验证包括真实目录字段读回、法师与标准角色分别学习、错误职业拒绝、技能点为零时拒绝，以及两类角色菜单与联机请求的 PIE 检查。

## 已实现与使用

人物窗口的技能页面默认显示“职业技能”。标准角色可以学习鬼斩·残月、血气爆发和暗月剑阵，法师可以学习冰棱裂爆、烈焰风暴和雷狱结界及原有法师技能。学习需要技能点，装备后的主动技能可放到数字快捷槽。近战的左右键继续使用武器基础动作，武器组的其他技能可以在武器技能页选择。

`FMyAbilityInfo.RequiredProfession` 是后续技能制作时填写的职业字段。角色菜单控制器获取当前角色目录，列表按职业过滤。服务端依据实际 Avatar/PlayerState、目录、Spec 类、技能状态和剩余点数校验请求。更改职业或读取旧存档时，目录外和其他职业的旧技能不会恢复为当前可用技能。

近战数字槽原先全部受武器组保护，现允许本职业目录内的技能通过原 ASC 装备事务替换。原武器授予/移除、被替换技能保存及换装恢复仍走已有装备组件。

## 验证

- UE5.8 Editor 构建成功，四个目录在独立进程读回职业字段及近战新增行。
- 最终 13 项原生回归通过，其中 3 项带警告。包括职业学习/非法职业请求/零点拒绝、存档与房间、六项新 GA 的 Actor 行为，以及武器装备事务和表现初始化。报告为 `Saved/Automation/ProfessionSkillsAccepted/index.json`。
- 法师和标准角色分别使用双客户端 Listen Server PIE。双方菜单均只显示本职业的新技能，远端依次学习、消耗点数并装备三项技能，服务器和客户端槽位一致。回执为 `Saved/GAAuthoring/ProfessionSkills/menu-mage.json` 和 `menu-stander.json`。
- 菜单行为验证采用 NullRHI，当前结果未包含改版页面的渲染截图或技能动画验收。
