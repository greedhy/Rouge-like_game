# 全量 GA 迁移、验证与本地 main 收口

## 完成标准

不是仅登记目录，也不是在新节点中再次激活一个完整旧 GA。公共行为必须可在同一执行协议下组合；已有 GA 路径、标签、输入、消耗、伤害、动画事件及表现保持可验证的兼容性。每个资产必须能追溯到实现、配置和测试证据。

自动化、资产读回、运行时验证与用户视觉验收分别记录。只通过构建不得标为迁移完成；无法由自动化覆盖的视觉项目保持待用户 PIE 验收。

## 实施裁定

- 在当前 `codex/unified-ga-environment` 完成迁移，按用户指定顺序在测试后合并本地 `main`，不再另建工作树。已有本地 UE 资产体积大且存在用户调参，不能克隆或清理为所谓干净目录。
- 三组独立任务可并行编辑互不重叠文件；构建、编辑器、命令行测试和 Git 操作由主任务串行执行，避免 DLL 与 SOMOLMCP 端口争用。
- 旧无限期 Orbit 使用显式流式兼容策略：活动状态、待处理队列、每帧处理量仍有界；不能用有限累计事件数意外停止已存在的开关技能。旧子行为总生成预算与队列预算分开，不能偷偷重置施法身份。
- 旧行为的 Actor/Mixed 差异是兼容契约，不借迁移统一数值或战斗规则。详细金样见 [18-kind 迁移计划](2026-11-09-unified-ga-kind-migration.md)。
