# 地牢光照审计与实施记录

日期：2026-11-19。依据用户需求审计 WorkBuddy 的《地下城主题光照方案_工作执行手册.md》。原文件作为美术建议保留，本文是实际执行修订。

## 审计结论

冷环境、暖光池、精英仪式光和 Boss 顶光可有效改善空间层次。原稿不能直接逐项执行：

- 持久关卡实际已有 SkyLight、SkyAtmosphere、ExponentialHeightFog、VolumetricCloud 和 PostProcessVolume，不能重复创建。
- 每房创建全局高度雾与“全场只有一个雾”的预算冲突。使用已有全局雾，随本地玩家所在房间过渡密度。
- 主题组件运行时读取 DA_Theme_*，覆盖方向光、雾、Bloom、材质自发光。Lava 原方向光为 2.8，仅修改关卡中的 0.15 会被覆盖。
- 8/20/40 未指定光度单位，无法作为可复现亮度。局部光显式用流明，方向光用 lux，曝光采用固定 EV100，强度以游戏视口调校。
- 当前整层 17 个房间同时装配。每房 ≤3 个阴影灯并不等于整个视图 ≤3 个，需要停用远房灯光和火焰，阴影只在本地玩家房间开启。
- 房间地面覆盖约 ±1200 cm，墙内沿约 ±1100 cm。照抄 ±1200 的火盆会埋入墙体或遮挡通路。火盆放在角部 ±850，并关闭碰撞和导航影响。
- 不承诺凭雾密度就得到 god-ray。需实际检查光束朝向、体积散射及摄像机视野，固定曝光下同时确认角色、预警、血迹和地面可读。

## 修订设计

房间子关卡各放一个 DungeonRoomLightingRig，入口放在持久关卡。原布局、种子、出怪、碰撞与流送逻辑保持现有路径。灯光组集中配置火盆、Niagara、局部光、房型差异和低幅闪烁，避免大量重复蓝图。艺术参数可在实例 Details 编辑，暂不创建重复的 DA_LightingPresets。

普通房四个暖光池和两处冷点缀；精英房增加紫红中央聚光与侧缘光；Boss 冷顶光、两侧主题色逆光和较弱火盆。功能房使用金色焦点、暖色休息区、商店灯串。复用 SM_Pillar、NS_Fire。闪烁用低频小幅强度变化，避免为每盏灯增加 Light Function 开销。

主题组件向灯光组提供主题色；全局雾由房型调整密度并保留主题颜色。低亮度冷补光和受控曝光维持暗部，主题材质降低自发光，防止整块地面发亮。游戏中的火焰仅当前房间开启，附近房间保留弱无阴影预照明。

## 约束与审核重点

在本地 main 修改，不推送，不混入既有用户改动。灯光组不复制玩法逻辑，不添加碰撞，不参与怪物攻击；专用服务器不运行表现 Tick。整层加载时远房无阴影和火焰。切主题不增加组件，房间退出和世界销毁由组件/Actor 生命周期清理。亮度最终按 PIE 画面判断，数值预算不等同于目标设备帧率保证。

## 最终参数和资产

| 项目 | 落地值 |
|---|---|
| 曝光 | 原有无界 PostProcessVolume，Min/Max EV100 均 0.5，补偿 0，暗角 0.28 |
| 全局补光 | 方向光 0.8 lux，冷蓝；SkyLight 0.08，关闭实时捕获。首轮 0.16 lux 过暗，按角色可读性回调；仍显著低于原主题的 2.2/2.8 |
| 天空 | 保留 Actor，隐藏日光大气/云，避免地牢外显示白昼；不使用需要可见天空的实时捕获 |
| 全局雾 | 沿用唯一 HeightFogComponent0，Z=-50，体积雾开启，距离 5000；基础密度 0.008，精英 ×1.6，Boss 基础 0.012 ×2.2；雾颜色降为暗色 |
| 火盆 | 默认 420 lm，半径 760 cm，暖橙，±6% 闪烁，四角 ±850；SM_Pillar + NS_Fire，装饰无碰撞、无导航影响 |
| 冷点缀 | 140 lm，半径 520 cm，普通房两盏 |
| 可读性补光 | 普通/功能房中央柔光 350 lm，朝战斗区斜射；特殊房使用各自聚光 |
| 精英 | 中央 1800 lm，边缘聚光 350 lm ×2，主题色与仪式紫混色 |
| Boss | 顶部冷色 3000 lm、两侧逆光 850 lm，火盆减弱；新增 DA_Theme_Boss，固定暗石/紫色，避免随机使用毒绿地面 |
| 裁剪 | 当前房全光与火焰，2700 cm 内邻房 18% 无阴影预照明，远房全关；采用当前 2400 cm 房间网格 |

入口及 CombatA~E、Elite、Boss、Treasure、Rest、Merchant 各保存一份原生 `DungeonRoomLightingRig`。在关卡中选择 `DL_*` 即可调节流明、闪烁和房型；组件面板可检查固定灯具。未创建原稿中的重复预设 DA、Light Function 或多份雾。原有主题 DA 均已同步方向光、雾、Bloom 和低自发光，Boss 资产会被原主题注册表自动读取。

## 验证结果

- 完整 Editor Development 构建成功；25 项自动化全部通过：灯光 2、主题 1、生成 9、对象池 7、BloodFX 6。测试日志 `Saved/DungeonLightingQA/automation.log`。
- 新灯光用例先在空实现失败，再在实现后通过。审查发现的门槛正中归属和远房配置激活问题均先重现失败，再修复通过；旋转模板、传送归属、重复配置不增加组件、无碰撞/导航均包含断言。
- PIE 仍为 seed=42，17 房全部 Ready，摘要 `4203e1ff75892b5badfe622330890ca1` 与原始基线一致，证明此种子的布局没有因布灯改变。测试覆盖额外的千种子生成规则，不能替代所有种子的美术巡检。
- 七种房型均在游戏视口核对真实 active room 后截图。入口/普通 7 灯/3 阴影/4 火焰；精英 9/3/4；Boss 7/2/4；宝藏 5/3/4；休息 6/3/4；商店 4/3/3。远房为 0/0/0。全局方向光另计。
- 固定 Boss 主题、冷顶光、紫色逆光和较浓体积空气已可辨认。画面采用柔和体积光，不将强边界的电影式 god-ray 列为已实现。
- 精英房 Frost→Lava 切换已巡检；房型灯数不变，灯色随主题过渡。原血迹/近战链路在正常战斗 PIE 中另行运行，未依赖美术巡检停战入口。
- 完整截图与每房生成回读在 `Saved/DungeonLightingQA/`。`boss.png`、`elite.png`、`combat.png` 为美术巡检；`live-combat.png` 为未暂停导演的正常战斗。美术巡检使用仅编辑器编译的 `Dungeon.Lighting.Preview` 临时停止战斗导演 Tick，防止门禁回拉；关闭 PIE 即恢复，不写入地图玩法状态。
- 唯一全局雾与 `r.VolumetricFog=1` 已核对。隐藏天空后的实时捕获警告通过关闭 SkyLight 实时捕获解决，最终截图无此警告。
- 性能快照保留真实数值：当前编辑器后台节流约 333 ms/帧、3 FPS，不能当作 GPU 基准或游戏帧率。工具中的 actor 数也来自编辑器世界。已验证组件数量与裁剪预算；目标硬件前台 GPU/战斗峰值压测、独立远端客户端和用户本人美术验收待后续专项执行。
- 独立审查的小项保留：低频 Tick 仍重复写入同值视距状态，可后续只在分级变化时更新。当前 17 房的 Tick 频率为 10 Hz，不据此承诺目标设备性能。
